Understand LLM pricing

How input, cached, and output tokens are priced — and what actually makes a request fast or slow.

How LLM pricing works

Every request is billed in four parts: the new prompt tokens you send, the prompt tokens reused from cache, the new tokens written into the cache, and the tokens the model generates back.

Worked example — GPT-5, the calculator's defaults: 100k uncached in + 1M cached in + 0 cache-write + 50k out, × 1,000 requests.

  • Uncached input: 100,000 ÷ 1M × $1.25 = $0.125 per request
  • Cached input: 1,000,000 ÷ 1M × $0.125 = $0.125 per request
  • Cache-write: 0 tokens × $0 = $0.00 (GPT-5's cache-write price isn't published, so the calculator counts it as $0)
  • Output: 50,000 ÷ 1M × $10.00 = $0.50 per request
  • Total: $0.75 per request × 1,000 requests = $750.00

Prices: provider list prices, checked Oct 2026 — verify before big commits. OpenAI · Anthropic · Google AI · xAI · DeepSeek

Cached vs uncached: why the cache is cheap

When a prompt (or part of it) repeats, the provider can reuse work it already did — so reusing cached tokens costs far less than processing new ones.

  • Cached-read is the price for reusing prompt tokens already in the cache. Cache-write is the one-off price for putting new tokens into the cache.
  • Cached reads run about 10× cheaper than uncached input on most models — GPT-5, Sonnet 4.5/4.6, Gemini Pro, Opus 4.8 and Haiku 4.5 are all exactly 10×. Exceptions: Grok 4.3 is 6.25× ($1.25 → $0.20), GPT-6.1 Sol is 20× ($2.00 → $0.10), DeepSeek V4 Pro is 30× ($1.32 → $0.044).
  • Caching pays off when the same prompt repeats — long system prompts, few-shot examples, or a big document you ask about many times.
  • Rule of thumb: writing a block to cache costs roughly 1.3–1.4× the saving from one reuse, so reuse the same cached tokens about twice and the write cost is covered (e.g. Sonnet 4.5: $3.75 write vs $2.70 saved per reuse).
  • Not every model charges a cache-write in this calculator: GPT-5's write price isn't published (counted as $0), and Gemini, Grok and DeepSeek show $0 — Gemini instead charges context-caching storage of $4.50/1M tokens/hour, which the calculator doesn't model.

Long-context tiering: prices jump above 200k tokens

Gemini 2.5 Pro and Grok 4.3 charge higher rates once a request's total input (uncached + cached) goes above 200,000 tokens. The calculator applies the higher tier automatically.

  • Gemini 2.5 Pro above 200k input tokens: input $1.25 → $2.50, cached-read $0.125 → $0.25, output $10.00 → $15.00.
  • Grok 4.3 above 200k input tokens: input $1.25 → $2.50, cached-read $0.20 → $0.40, output $2.50 → $5.00 — everything doubles.
  • The trigger is total input (uncached + cached tokens together), not output length — a short question over a huge cached document can still trip it.
  • Only these two models in the calculator have a long-context tier; the others charge one flat rate at any length.
  • Side notes the calculator doesn't model: Grok's 20% batch discount, and Gemini's $4.50/1M tokens/hour cache-storage charge.

Speed: time to first token vs decode vs tokens/sec

A request has two phases: prefill (the model reads your whole prompt at once) and decode (it writes the answer one token at a time). Prefill is fast; decode is the slow part.

  • TTFT (time to first token) = prompt tokens ÷ prefill speed. Worked example: 2,000 ÷ 2,000 tok/s = 1 s. Longer prompts mean a longer wait before anything appears.
  • Decode = output tokens ÷ decode speed. Worked example: 500 ÷ 50 tok/s = 10 s. Longer answers dominate total time.
  • Effective tokens/sec = (prompt + output) ÷ total time = 2,500 ÷ 11 s ≈ 227 tok/s. It blends both phases, so it looks faster than the 50 tok/s decode rate — don't compare it directly with a decode-only number.
  • Concurrency splits the decode speed between simultaneous requests: at 2 concurrent requests each one decodes at 25 tok/s, so each takes twice as long to finish.
  • What affects each: prompt length drives TTFT; output length drives decode; concurrency and server load slow decode for everyone sharing it.

Model prices at a glance

All 14 presets in the calculator, base rates per 1M tokens. Output is almost always the bigger number — and the bigger cost driver.

  • Cheapest overall: GPT-5.6 Luna ($0.20 in / $1.20 out) and Gemini 2.5 Flash ($0.30 in / $2.50 out) — roughly 20× cheaper than Opus on output.
  • Most expensive: Claude Opus 4.8 ($5.00 in / $25.00 out), then GPT-5.6 Sol ($4.00 in / $20.00 out).
  • Output costs 2–10× input on every model here — Grok 4.3 is the narrowest gap (2×), GPT-5 the widest (8×). Long outputs dominate the bill.
  • Base rates shown. Gemini 2.5 Pro and Grok 4.3 charge more above 200k input tokens (see the tiering section above), and GPT-5.6 Sol is on promotional pricing through Nov 21, 2026.
  • DeepSeek V4 Pro shows peak-hour prices; off-peak is half. Try the calculator above with your own token counts to compare models on your workload.

How to estimate tokens

As a rough rule, 1 token ≈ 4 characters of English text, or about 0.75 words per token — so 100 words is roughly 133 tokens. Code, non-English text and unusual formatting can tokenize differently, so treat this as an estimate, not an exact count.

  • Paste your actual text into the token estimator on the Dev tab for a quick estimate before you price a request.
  • Remember: the prompt you send counts as input tokens, and everything the model writes back counts as output tokens — usually the pricier kind.
